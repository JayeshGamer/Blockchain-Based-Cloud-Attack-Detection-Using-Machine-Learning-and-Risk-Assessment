# Research Limitations & Honest Scientific Assessment

## 1. Dataset & Development-Test Exposure

- **Dataset Re-use**: The evaluation is conducted on the benchmark **CICIDS2017** dataset. Like many studies in academic network security literature, this benchmark has been examined repeatedly during development and exploratory phases. Although we strictly enforce chronological splits and fit scalers only on Monday data, the hyperparameter defaults (such as SGD `alpha=1e-4`, standard penalty, threshold $\tau=0.50$) reflect standard conventions known to function reliably on this dataset.
- **Known Artifacts of CICIDS2017**: Recent literature has noted synthetic artifacts in CICIDS2017, including packet generation flaws, port-scanning patterns with fixed inter-arrival times, and certain metadata regularities. Performance on this dataset may not directly reflect zero-day behavior on unstructured real-world enterprise traffic.

---

## 2. Evaluation Scope: Stratified Sample vs. Full 2.8M Flows

- **Evaluation Scope Completed**: The final reported evaluation was performed on a rigorously sampled, chronologically ordered stream:
  - **Warm-up / Baseline**: 8,445 Monday benign flows.
  - **Streaming Evaluation**: 41,555 flows spanning Tuesday through Friday captures (15,000 attack flows and 26,555 benign flows).
  - **Total Processed in Evaluation**: 50,000 flows across 42 batches.
- **Full-Data Status**: The complete raw CICIDS2017 dataset consists of approximately 2,830,743 raw network records across 8 distinct CSV files. Running full continuous online SGD replay over all 2.8 million flows requires multi-hour computation and hundreds of gigabytes of intermediate memory if uncompressed. While the chronological prequential protocol was tested and validated on 50,000 flows to verify mathematical correctness, **the full 2.8 million flow run has not been completed as part of this release package**.
- **Claims**: We explicitly document results as evaluated on the 50,000-flow chronological stream protocol, and make **no claim** of full-scale 2.8-million-row completion.

---

## 3. False Alarms and Missed Attacks

- **False-Positive Trade-off**: The primary Online SGD model achieves a **2.66% False-Positive Rate (FPR)** (707 false positives out of 26,555 benign flows). While 2.66% is competitive in research benchmarks, in a high-bandwidth cloud environment handling $10^7$ flows per hour, a 2.66% FPR would generate ~266,000 false alerts per hour, overwhelming security operations centers (SOCs). Operational deployment would require stricter operating thresholds ($\tau \ge 0.85$) or secondary alert triage.
- **Missed Attacks (False Negatives)**: The primary SGD model exhibits a **13.12% False-Negative Rate (FNR)** (1,968 missed attacks out of 15,000 attack flows; recall = 86.88%). Missed attacks predominantly consist of subtle infiltration attempts and stealthy web-layer probes (e.g., SQL Injection and Cross-Site Scripting) whose aggregate flow statistics closely mimic legitimate HTTP traffic.

---

## 4. Input Requirements: Flow Features vs. Raw Packets

- **Flow-Level Dependence**: The system operates exclusively on **precomputed bidirectional network flow records** (such as those generated by CICFlowMeter or Argus).
- **Not a Raw Packet Sniffer**: The system **cannot** directly inspect raw PCAP or live packet streams without an upstream feature extraction pipeline that computes flow statistics (e.g., flow duration, inter-arrival times, packet length statistics).
- **Latency Delay**: Flow features can only be computed upon flow termination or after active timeouts (e.g., 15–120 seconds), introducing an inherent architectural latency before an attack can be classified.

---

## 5. Simulation Assumptions

- **Delayed Label Availability**: In our evaluation, labels are assumed to arrive with a delay of $D = 1$ batch (1,000 flows). In actual cloud operations, obtaining true attack labels requires human analyst triage, honeypot confirmation, or retrospective threat intelligence feeds, which often introduces delays ranging from hours to days.
- **Defense Mitigation**: The simulated defense engine models IP rate-limiting, container isolation, and VM migration via state machine counters. It has not been tested against live hypervisors (KVM/QEMU) or software-defined network (SDN) controllers under live DDoS traffic.
- **Blockchain Throughput**: The blockchain audit ledger was validated using an in-memory mock and local JSON-RPC nodes. Public or permissioned blockchain latencies (block times of 2–15 seconds) and gas costs were not benchmarked under gigabit ingress rates.

---

## 6. Novelty and Research Claims

- **Standard Linear Model**: The primary streaming model is standard Stochastic Gradient Descent (`SGDClassifier`). **It is not a novel algorithm.**
- **DST Performance Regression**: Dempster-Shafer Theory (DST) was hypothesized to improve detection robustness by fusing classifier and anomaly evidence. However, empirical evaluation revealed that ML-DST under standard decision thresholding ($\tau=0.50$) achieved significantly lower recall (42.69%–47.25%) than single-model SGD (86.88%). **No claim of DST superiority is made.**
- **No Publication Guarantee**: This project represents a clean, reproducible, methodologically sound research implementation and evaluation pipeline. High benchmark accuracy on CICIDS2017 alone does not establish scientific novelty or guarantee acceptance in top-tier venues (such as IEEE S&P, USENIX Security, or IEEE TDSC) without novel theoretical contributions or comprehensive real-world validation.
